# Aliyun OSS temporary reference staging
OSS is the required reference URL transport for direct Metaso video; it is not game hosting or canonical storage. Owner supplies existing bucket/region or separately approves provisioning. Private bucket, block public access, HTTPS, RAM least privilege limited to project staging prefix (Put/Get and scoped cleanup only as needed), preferably STS or securely stored dedicated RAM credentials. No root account keys. Use official OSS SDK, no hand-built signing. Confirm public endpoint or CNAME and certificate; new mainland OSS accounts may require a custom domain for data operations. Verify actual account and region; do not create a domain/bucket in Phase 0.

Object key: staging/existence-paradox/<sha256>.<ext>; use metadata/content-type and local hash to deduplicate. Store only object key/hash, not signed URL. Issue short-lived signed GET URLs near submission (suggested 2 hours, adjust to queue/fetch window and STS expiration); check from a non-authenticated network GET before pilot. URLs are bearer-like secrets; no logs, Git, task files, browser or other worker context. Signed URL acceptance by Metaso is not yet verified. If rejected, block and investigate; never make bucket public automatically. For concurrent jobs retain object until all references finish or unknown jobs reconcile. Use lifecycle fallback (suggested 7 days, owner confirms adequate for reconciliation); no premature deletion. Keep permanent local sources and outputs. Budget includes storage, requests, public egress and optional domain costs. No actual SDK dependency, cloud resources, upload or live URL verification included.
Sources: https://help.aliyun.com/zh/oss/developer-reference/download-objects-using-a-presigned-url-generated-with-oss-sdk-for-node-js ; https://www.alibabacloud.com/help/zh/oss/user-guide/upload-files-using-presigned-urls ; https://help.aliyun.com/zh/oss/user-guide/access-oss-via-bucket-domain-name .
