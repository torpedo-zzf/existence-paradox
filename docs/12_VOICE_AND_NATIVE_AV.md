# Voice-first, native audiovisual production (authoritative)
Owner decision: local OmniVoice establishes immutable character voice identities BEFORE cinematic generation. Codex writes dialogue, voice direction and shot timing; agy controls local OmniVoice and OSS/Metaso; DeepSeek Harness checks audio/video integrity and assists local batch processing. Only agy approves staging and paid jobs.

## Voice bible and assets
Use synthetic original voices or explicitly authorized voice sources. Assign VOICE IDs and bind each to CHAR ID and revision. Store reference WAV/MP3, transcript, language, speaking pace, emotion, local model/version, hash and rights. Keep local canonical references immutable; one reference voice per speaker. Produce clean speech-only 2–15 s clips, max 3 audio clips and 15 s total per H3 reference request (official constraints; confirm Metaso). For the pilot use a single speaker and a 4–8 s dialogue sample. Do not upload raw unapproved voice material. Qwen and OmniVoice local inference serial initially.

## Native AV generation
For speaking shots use direct Metaso MiniMax-compatible V2 reference-to-video with approved reference_image and reference_audio entries in content, exact dialogue in prompt, speaker-to-reference mapping, intended delivery and duration. Request native audio (generate_audio=true where confirmed supported). Never use OpenAI compatibility for reference audio; do not mix first_frame/last_frame roles with reference_audio under native H3 rules. Reference audio steers voice and delivery; exact waveform preservation, exact words, and lip sync are NOT guaranteed. Do not assume a separate audio-driving endpoint exists. Confirm actual Metaso schema before implementation; if audio input or native output unavailable, block speaking-shot production, do not silently switch provider or dub over generated mouths. Non-speaking shots may use image-to-video or reference-to-video with native ambience.
Stage images AND audio via private OSS signed HTTPS GET URLs; check rights, fetch acceptance, TTL and budget. Never log URLs or secrets. Use only approved direct Metaso provider, no ComfyUI for video. Preserve native dialogue track; FFmpeg edits, mixes ambience/music without overwriting speech, normalizes loudness, encodes and verifies output. Runtime dynamic NPC speech uses local OmniVoice separately, with subtitles or non-speaking portraits, not forced lip sync on prerecorded speaking video.

## Pilot and release gate
After approved local voice generation and OSS staging, run a separately approved 768P one-speaker pilot with a canonical actor image, canonical voice reference, exact short dialogue and enough pause. Compare two independently generated shots for voice consistency if budget authorizes. Record actual task IDs, local file hashes, ffprobe audio/video streams, duration, actual cost, transcript comparison, human/Codex review of lip sync and timbre, plus pass/reject with evidence. Check no omitted/added words, acceptable lip sync, correct speaker and consistent voice. Technical stream presence is NOT proof of lip sync or identity. Reject and request bounded re-generation approval if not acceptable; consider off-screen dialogue/subtitles or non-speaking shots only with owner approval. Do not substitute post-dub as default. No real inference, upload or paid request in Phase 0. No live integration is claimed.
