# DeepSeek integration — planned, disabled by default

## Two independent roles
- Development: planned DeepSeek Harness worker for isolated test generation, review, data validation and small bounded implementation tasks. agy remains lead and sole human-facing coordinator. Do not assume a harness binary, subscription, login, invocation syntax or compatibility exists. Inspect locally without logging in or installing; use the official supported distribution and authentication only after owner approval. An unavailable worker is not a Phase 0 failure. No simultaneous workers before authorization and distinct worktrees.
- Runtime: DeepSeek API is the preferred candidate for bounded Chinese NPC dialogue and player intent recognition in Phase 3. A fast/low-cost model is preferred after real latency, quality and cost tests; model ID, endpoint and pricing are intentionally unspecified until verified against official documentation. Development subscriptions or harness credentials do not imply API entitlement. No new subscriptions or API requests during initialization.

## Runtime boundary
Browser -> server-side dialogue adapter -> policy/authorized context -> DeepSeek -> strict output validation -> dialogue display -> optional local OmniVoice. Core engine exclusively controls state, facts, evidence and endings. DeepSeek is not a director, game-state writer, media generator or unrestricted agent. Send only NPC-specific canon, allowed known fact IDs, capped conversation and current player question. Do not include secrets, hidden future facts, raw save data, or arbitrary tool access. Treat player input, provider output and retrieved text as untrusted. Never expose API credentials or internal system prompts to browser clients. Use an authored fallback on errors, invalid output, unknown facts, prompt injection attempts, quota/budget limit, timeout or unavailable network. Provider output cannot directly perform any state transition, even when it passes schema validation. Semantic review is needed because schema validation alone cannot prove a statement true or prevent spoilers.

## Budget and reliability
Default mock provider; no network in Phase 0 or 1. Before real use obtain explicit owner approval for model ID, endpoint, credential provisioning, per-session turn and token limits, timeout, concurrency, retries and spending cap. Fail closed on missing or invalid budget configuration; account for in-flight requests before dispatch. Bound request/context size, no unbounded retry, no per-frame generation. Avoid retrying chargeable ambiguous failures automatically. Keep authored dialogue available at all times. Track latency, request count, token usage, estimated costs (label estimates) and error category without storing private dialogue or credentials. TTS runs separately; failed TTS falls back to subtitles. No assumption that DeepSeek has native voice or video generation.

## Gates
Phase 0: read this document, parse config and run offline contract tests; optionally report harness presence using local PATH lookup only. No login, API calls or secret printing. Phase 1: authored/fixture dialogue only; no dependency on runtime model. Phase 3 (after MEDIA-201): implement server adapter and mocked tests, owner approves configuration and limited paid smoke test; compare latency, consistency and cost with authored fallback. The planned dev worker can be assigned only after owner approval, actual installed tool verification and task ownership review, regardless of runtime phase.

## Handoff
Worker output follows orchestration/TASK_PROTOCOL.md. agy independently reviews diffs and runs tests. For runtime acceptance, prove timeout/quota/invalid output/unknown facts/extra fields cannot mutate the state; demonstrate offline completion and no key in client assets. Real adapter and connectivity are not included in this baseline. Configuration fixture is a contract, not a working API integration.
